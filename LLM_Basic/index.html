How a large language model actually works

Eight stops, in the order a sentence actually travels through a model: split into tokens, looked up as vectors, mixed by attention, stacked into layers, shaped by training, and finally decoded back into words.

01

Tokenization & embeddings

Models don't read letters or words — they read integers. A tokenizer chops text into a fixed vocabulary of chunks, then each chunk is looked up as a vector that encodes its meaning.

Text → tokens

Subword tokenizers (BPE, WordPiece) split rare words into pieces so the vocabulary stays small

"unbelievable"
→
un
believ
able

Common words stay whole; rare or made-up words get split into familiar fragments. This is why a model can handle words it never saw during training.

Token → embedding

Each token ID indexes into a lookup table of learned vectors

embedding = LookupTable[token_id]
+ PositionEncoding[position]

The position encoding is added because attention itself has no sense of order — without it, "dog bites man" and "man bites dog" would look identical.

02

The core idea: attention

Each token asks what matters, scores every candidate, then blends their information.

Query, key, value

Q and K decide relevance; V carries the content

token state x
↙↓↘
Q = xW_Q
what am I looking for?
K = xW_K
what do I match on?
V = xW_V
what information do I provide?

Scaled dot-product attention

Similarity, scaled, normalized, then blended

Attention(Q,K,V) =
  softmax( QKT / √d_k ) · V

Dividing by √d_k keeps scores from growing too large as dimensions increase — without it, softmax would saturate and gradients would vanish.

05

Encoder-only, decoder-only, encoder-decoder

The block from the last section can be wired together three different ways, depending on whether the model needs to understand text, generate text, or transform one sequence into another.

Encoder-only

Bidirectional attention · outputs one vector per input token

input tokens
→
bidirectional encoder × N
→
contextual embedding per token

Attention: full square — every token sees every token.
Trained on: masked language modeling (guess the missing word).
Good at: classification, search & retrieval embeddings, named entity recognition.
Examples: BERT, RoBERTa.

Decoder-only

Causal attention · generates one token at a time

tokens so far
→
causal decoder × N
→
next token
↻ fed back in

Attention: lower triangle — each token sees itself and the past only.
Trained on: next-token prediction over raw text.
Good at: open-ended generation, chat, code, reasoning.
Examples: GPT, Llama, Claude — almost every modern general-purpose LLM.

Encoder-decoder

Bidirectional encoder + causal decoder, linked by cross-attention

source text
→
encoder
↘ cross-attention
target so far
→
decoder
→
next token

Attention: encoder is a full square; decoder is a lower triangle that also cross-attends to every encoder position.
Trained on: sequence-to-sequence tasks — one text in, a different text out.
Good at: translation, summarization, speech-to-text.
Examples: the original 2017 Transformer, T5, BART, Whisper.

Decoder-only won out for general-purpose assistants because a single causal stack can absorb almost any task as plain text, with no separate encoder needed. Encoder-decoder still wins when input and output are structurally different in kind, like audio in and text out.

07

Inference & decoding

The model outputs a probability for every token in its vocabulary. Temperature and top-p decide how that distribution turns into an actual choice.

Low temperature flattens toward the top candidate (predictable, safe). High temperature flattens the distribution (more variety, more risk of nonsense). Top-p cuts off the long tail entirely before sampling.

Scaling laws & context

09

Efficient attention variants

Standard attention forms an n×n score matrix — O(n²) compute and memory. These variants reduce which pairs are computed, change the underlying math, or execute the same math more efficiently.

Sparse attention

Compute only selected Q-K pairs

Local windows plus a few global tokens. Misses some long-range links in exchange for O(n·w) cost. See: Longformer, BigBird.

Linear attention

Reorders a kernelized approximation

φ(Q)(φ(K)ᵀV)

Avoids ever materializing the full QKᵀ matrix — often O(n). Quality depends heavily on the choice of kernel φ.

FlashAttention

Same exact result, memory-aware execution

Q
→
K,V
→
tile

Tiles the computation through fast on-chip memory. Still O(n²) math, but with far less memory traffic — exact, just faster.

Sparse changes which pairs exist; linear changes the formulation; FlashAttention changes only the implementation.
